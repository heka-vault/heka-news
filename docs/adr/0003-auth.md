# 0003. Auth: GitHub OAuth and invitation links

- Status: accepted; implemented in phase 3. ADR 0007 has the details (OAuth state and PKCE,
  sessions, CSRF, invitations, rate limits)
- Date: 2026-10-18
- Amended: 2026-10-18, moderators can make other members moderators (migration 0003)

## Context

Anyone can read. Only members can post, comment, vote and flag, and membership is by invitation:
the engineers in heka's group, and people they invite. We do not want to run email delivery or
store passwords at launch.

## Decision

- **Sign-in is GitHub OAuth.** A user row stores the GitHub numeric id (stable across renames)
  and the login (shown, and used in URLs as `/u/:login`).
- **Joining needs a one-time invitation link.** A member creates an invite; the link carries a
  random token. Only the token's SHA-256 is stored (`invites.code_hash`). Following the link and
  signing in with GitHub creates the account with `invited_by` set, and marks the invite used.
  Invites expire after 14 days and can be revoked. Founding moderators need none: their first
  sign-in makes them roots of the tree.
- **The invite tree is public** (`/tree`), as on Lobsters: who invited whom is part of how the
  community holds itself accountable.
- **Sessions live in SQLite** (`sessions`), keyed by the SHA-256 of a random token in an
  `HttpOnly`, `SameSite=Lax` cookie named `heka_session` (`Secure` when the site is https), for 30
  days from the last visit. Signing out deletes the row; a ban deletes all of them.
- **Founding moderators are configured by GitHub login** (`MODERATORS`, comma-separated). Signing
  in sets `users.is_moderator` for them and never clears it for anyone. Every moderator action
  writes a `mod_log` row, shown publicly at `/moderation`.
- **Moderators make other moderators from the site.** On a member's profile, a moderator can make
  them a moderator or remove them as one, with a reason, logged as `promote_moderator` or
  `remove_moderator`. Nobody changes their own status, a banned member cannot be made a moderator,
  and a founding moderator cannot be removed from the site (sign-in would restore it). Sessions read
  `is_moderator` from `users` on every request, so a change applies at the member's next request;
  removal does not sign them out.
- **Moderators cannot be banned.** Remove the moderator status first. For a founding moderator
  that means taking the login out of `MODERATORS`, then removing them on the site, then the ban.
  One rule for every moderator, and the order is visible in the log.
- **No email at launch.** Nothing needs it: no password resets, no notifications.

## Consequences

- Until the GitHub app's credentials are set, there is no sign-in: "Sign in" explains that
  membership is by invitation and sign-in opens soon.
- A response to a request carrying the session cookie is `private, no-store`; anonymous pages are
  cacheable by a shared cache. The switch is implemented now (`src/lib/http.ts`).
- GitHub is a dependency for signing in, not for reading.
- Taking a login out of `MODERATORS` no longer demotes it: it becomes an ordinary moderator, whom
  another moderator can remove from the site. Before migration 0003 sign-in mirrored the list in
  both directions, which would have undone every change made on the site.
- The site's copy gives no count of moderators.
